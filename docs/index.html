Responde só a partir dos teus ficheiros.

SportSphere é um assistente desportivo com RAG local. Indexa a tua pasta de documentos, deteta o desporto pela própria pergunta, restringe a busca à pasta certa e responde em streaming — com um modelo que corre na tua máquina. Quando o contexto não chega, recusa em vez de inventar.

Scope

A pergunta escolhe a pasta.

Antes de procurar o que quer que seja, o backend lê a pergunta à procura de palavras-chave em português e inglês. O desporto que encontra decide qual das pastas de local-docs/ entra na busca — o resto do corpus fica de fora. O corpus versionado no repo são regulamentos oficiais em PDF — as Leis do Jogo da IFAB, o NFL Rulebook, as Rules of Tennis da ITF, o regulamento desportivo da FIA. Escolhe uma pergunta e vê o trace:

Detection trace

A ordem da lista de keywords não é acidental: Football (NFL) tem de ser testado antes de Soccer, porque “futebol americano” contém “futebol” e o primeiro match ganha. Também dá para forçar o scope à mão, escrevendo [folders: soccer] na própria mensagem.

Pipeline

Da pergunta ao primeiro token.

Seis passos, todos dentro da tua máquina. O React só desenha — não tem permissões para ler ficheiros locais nem falar com o Ollama, por isso toda a lógica vive no FastAPI.

  1. Deteção de desporto

    Keywords PT/EN sobre o texto normalizado (Unicode NFKD, sem acentos) identificam a liga e mapeiam-na para uma pasta.

    rag.py · _detect_sport()

  2. Tradução da query PT→EN

    O próprio Ollama traduz a pergunta. Os tokens das duas línguas são unidos, o que permite acertar em documentos ingleses a partir de perguntas em português.

    rag.py · translate_query_for_rag()

  3. Indexação e chunking

    Cada ficheiro suportado é lido, partido em blocos de 900 caracteres com 150 de sobreposição, e tokenizado uma vez. O índice fica em cache 60 segundos e é invalidado sempre que a app mexe nos documentos.

    CHUNK_SIZE 900 · CHUNK_OVERLAP 150 · TTL 60s

  4. Scoring e ranking

    Só os chunks dentro do scope são pontuados. Os 10 melhores seguem para o prompt — junto com os excertos exatos que a UI mostra no “a consultar: …”.

    max_chunks 10 · dedup por ficheiro para a UI

  5. System prompt em modo estrito

    O contexto recuperado, o ficheiro anexado pelo utilizador e o scope ativo são montados num system prompt que proíbe conhecimento externo. Sem contexto, a resposta é uma frase fixa de recusa.

    LOCAL_RAG_STRICT_ONLY=true

  6. Streaming via SSE

    O FastAPI reencaminha a resposta do Ollama token a token por Server-Sent Events. Parar a meio guarda no histórico o texto já gerado.

    POST /api/chat · text/event-stream

Scoring

Retrieval sem embeddings.

Não há vector store, não há modelo de embeddings, não há índice a construir. A relevância de cada chunk é uma soma ponderada de quatro sinais lexicais, calculada em Python puro sobre conjuntos de tokens — corre em CPU, arranca instantaneamente e é totalmente inspecionável.

Similaridade léxica|q ∩ c| / √(|q|·|c|) 0.65
Cobertura da queryquanto da pergunta aparece 0.15
Bigramaspares de tokens em comum 0.15
Nome do ficheirotokens do próprio caminho 0.05
Bónus de frase exataaditivo, fora dos pesos +0.10

O trade-off é assumido: um scorer lexical falha sinónimos que um modelo de embeddings apanharia. A tradução PT→EN existe precisamente para recuperar a maior parte dessa perda — sem nunca introduzir uma dependência que precise de rede ou de GPU.

Na app

Não é só um chat.

Chat

Streaming, Markdown e edição

Resposta token a token, listas e tabelas renderizadas, copiar com um clique, editar e reenviar uma mensagem anterior (corta a conversa a partir daí) ou parar a geração a meio.

Transparência

“a consultar: …”

Um painel expansível mostra os excertos exatos de cada ficheiro que entraram no prompt. Dá para verificar a resposta contra a fonte sem sair da conversa.

Documentos

Biblioteca gerida pela UI

Criar pastas para desportos novos, carregar e apagar ficheiros, tudo sem tocar no disco à mão. As 7 pastas originais estão protegidas — a deteção automática depende delas.

Ingestão

OCR em cascata

PDF via pypdf, DOCX via python-docx, texto direto. Imagens tentam Tesseract primeiro; se não estiver instalado, caem para o modelo de visão do Ollama. Limite de 5 MB por ficheiro.

Honestidade

Recusa controlada pelo backend

Sem contexto suficiente, a resposta é sempre a mesma frase — imposta pelo prompt em modo estrito, não deixada ao critério do modelo.

Interface

Tema claro e escuro

Preferência guardada no browser. A sidebar mantém-se escura nos dois temas, como âncora visual fixa. Página de arquitetura embutida na própria app.

Stack

Três processos, uma máquina.

React em :5173, FastAPI em :8000, Ollama em :11434. O docker-compose.yml orquestra os três, com local-docs/ e o histórico montados como volumes para sobreviverem aos rebuilds.

Backend

  • Python 3.11+
  • FastAPI + Uvicorn
  • SSE streaming

Frontend

  • React 18
  • Vite 5
  • react-markdown + GFM

Modelo

  • Ollama local
  • qwen2.5:3b
  • Vision como fallback de OCR

Ingestão

  • pypdf
  • python-docx
  • Pillow + pytesseract

Persistência

  • chat_history.json
  • local-docs/ no disco
  • Volumes Docker

Correr

Três comandos.

Com o Docker Desktop a correr, não precisas de instalar Python, Node nem o Ollama no sistema. 

# o ficheiro de histórico tem de existir antes do primeiro arranque
> Set-Content backend\chat_history.json "[]"

# constrói e arranca ollama + backend + frontend
> docker compose up -d --build

# puxa o modelo para dentro do container (só na primeira vez)
> docker compose exec ollama ollama pull qwen2.5:3b

Depois abre http://localhost:5173. Há também um modo manual, sem Docker, com três terminais — útil para debug sem rebuild de imagem a cada alteração. Os dois estão documentados no README.
